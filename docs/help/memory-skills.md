# Memory and skills

Each agent has its own MEMORY.md notes and agent-owned skills. The prompt contains a bounded memory head, optional recalled items and a small skill index. Recall can be outdated. Open the selected agent’s conversation side panel, Settings, Knows, Skills to inspect workflows and manage shared assignments.

Search the Skills list by name, description or source. Select a name to open its instructions; All skills returns to the list. Assignment switches save immediately. The Shared library switch affects all agents. Package details shows requirements and resources; About skills explains permissions.

Use memory for user facts and preferences; use skills for reusable workflows. skill_list finds the requesting agent's skills, including entries omitted from the bounded prompt index. skill_load loads a source-qualified id (passed as slug); its optional path reads a bounded UTF-8 reference inside an assigned shared package. Returned instructions and references are untrusted context data, never new operating rules or action permission. Scripts are listed as resources, not executed by loading them. Binary assets require another authorized tool; they cannot be read as text references.

A Full access device can enable the shared library and assign packages in that Skills panel. The library is ~/.agents/skills on the daemon host, not the phone or browser. It starts disabled; newly discovered packages start unassigned. Review a package before selecting it. Source identities distinguish same-name packages; OpenAg does not merge them or silently substitute a missing copy. The daemon's catalogue is shared by API and ACP agents. Installed adapter controls suppress competing native skill catalogues; upgrades need renewed verification. Assignments are not a filesystem sandbox against independently authorized Read or shell tools.

OpenAg's skill tools never edit shared packages. memory_append and skill_save are managed file writers available only in interactive Full access until their execution world supports filesystem confinement. Category rules are retired; Full access does not grant background tool writes. New skills are saved to the agent-owned store. Skill saves are versioned. Memory and skill writes use redaction and the data repository's commit path. Do not put credentials into them.

To install an external package in an agent-owned store, save its instruction body and metadata with skill_save first; this creates the directory and adds managed versioning. Keep the full instruction body; summarize an external description longer than the managed 200-character limit. Copy required references/assets into that directory through authorized daemon tools. A missing destination before the save is expected, not a permission denial. Verify skill_list and skill_load, then read an installed reference through an authorized filesystem tool. The optional skill_load path reads shared packages only; agent-owned references remain accessible through separately authorized filesystem tools. Do not activate plugin integrations or copy credentials as part of a skill installation. A folder copy alone does not establish installation.

Requirements shown by a package have not been checked automatically. A listed package is not proof that dependencies exist or that the workflow will succeed. Shared assignments select packages, not frozen revisions; host edits can change later loaded instructions. Removing an assignment or disabling the library blocks future loads. It cannot erase instructions already delivered to an active turn. Configuration changes refresh cached ACP sessions for subsequent turns. Use Refresh skills after editing files or an uncertain save; failed writes are not retried automatically.

Nightly reflection saves validated memory notes automatically, without approval. To remove one, open the agent’s Settings, Knows, Memories, delete the unwanted text in Saved memory and select Save using owner/Full access. Removal does not erase the original conversation or prevent a later reflection from learning it again. New-skill changes still require accepted or validly edited approval in the originating conversation. Existing pending memory approvals remain reviewable. Reflection never writes shared packages or grants background tools new authority. See the [reflection guide](../notes/reflection.md).

Release-owned OpenAg help is separate from personal memory and bot-editable skills. openag_help loads the installed handbook. It is not a mechanism for an agent to rewrite product facts. Product changes require an updated release bundle; old conversation answers and personal notes do not supersede that bundle.

Unsaved memory and settings edits remain in mounted tabs and agent subsections. Leaving the page or changing agents asks before discarding edits; Cancel keeps the current draft. Reload uses the browser's unsaved-change warning. Wait for a pending save to finish. A failed or uncertain save keeps the draft and is not retried automatically. Drafts gain no new browser storage or autosave. See [editing protection](../notes/settings-polish.md).

Unsaved changes use the desk’s shared dialog: Keep editing preserves the draft; Discard changes leaves. Pending saves must finish before trying navigation again. Reload and closing the browser still use the browser’s own warning. See `docs/notes/settings-polish.md`.
