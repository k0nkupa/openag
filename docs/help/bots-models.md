# Bots and models

Off-screen avatars pause their animation and resume with their current appearance and expression when visible again. This does not change Animate avatar or agent state. See `docs/notes/avatars/README.md`.

Bots have their own instructions, memory, skills, work directory and permission modes. The default is marked in its bot settings. Selecting a default does not grant owner rights or membership in every room.

Select an agent in the sidebar, open its side panel. Settings is the default tab. Brain contains model settings; Knows contains instructions, memories and skills; Session permissions are in the conversation composer or `/permission`; Server settings owns future defaults and upgrade adoption. Model settings distinguish the runtime (ACP or API), adapter (such as Claude Code or Codex), provider, requested model and reported model. Cached model choices load automatically when Model and reasoning opens. Use the shared shadcn model menu grouped by source; there is no adapter/provider dropdown. Refresh models in Settings → Models updates the saved catalogue. Effort options come from the saved per-model metadata, retaining supported values. Selecting Ollama or a subscription adapter can change an existing agent’s runtime. See docs/notes/model-picker.md for behavior and limits. An administrator environment override can take precedence over stored API model settings. Credentials and adapter installation remain administrator-managed.

Requested configuration is not proof of what ran. Status preserves session and response reports separately: session reasoning can coexist with a different returned model. Each last-reported model/reasoning value belongs to its observed session or response and may be from a previous configuration. The conversation context panel shows the saved model and reasoning, plus the last runtime report for this room (or the newest from another room, labelled). If no runtime evidence exists, say Not reported. Use openag_status for this bot and room; do not infer a model from an adapter name.

Use the plus beside Agents in the sidebar to open New bot. Owner or Full access is required. Enter a name, optional description and instructions, choose a model and effort, then create. Names may repeat; each bot receives a unique, stable @handle. Creation does not run a turn, create Work or change the default bot. The desk then opens the new agent’s direct conversation using the usual chat action. If creation is uncertain, keep the draft and check creation status before retrying. Model lists and reasoning options are cached on the server and survive restart. Opening, selecting and saving use cached metadata without live discovery. Sources refresh daily. Use Settings → Models → Refresh models to update them now; a failed refresh keeps the last successful choices and shows its age. A first install waits for its initial background refresh. Creation and saves validate the cached model and reasoning; changed catalogue choices require review. Existing agents can switch to Ollama and back through Model and reasoning without losing identity, conversation records, memory, skills or permissions. Saving does not start a turn. The next runtime session applies the selection; cached availability does not prove inference works. The memory embedding model is separate. See [model selection and refresh](../notes/model-picker.md). Try again under Unavailable model sources rereads cached data. Use Refresh models to contact the source; no write is automatically retried. Management tools cannot create bots; credentials and adapter installation remain administrator-managed. Default-bot creation on startup is separate. See docs/notes/bot-creation.md for behavior and acceptance limits. Model switching and discovery code exists, but complete acceptance across real providers/adapters is still pending; unavailable paths must report their reason.

Bot settings live in the selected agent’s conversation side panel, on the default Settings tab. Work, Files, Computer and Activity remain separate tabs; no extra Bot settings button is needed. Sections expand inline in that same panel, without a Back step. Closing a section keeps its draft. Full ledger is in Activity. Name, description and instructions use Save/Discard; other editors retain their own save controls. Switching back to Work or hiding the panel keeps the mounted editor draft. Old Bots bookmarks open an agent conversation; there is no standalone Bots settings page. On Models, configured API providers remain visible separately; Browse all supported providers opens the searchable catalogue, and Setup reveals commands for an unconfigured provider. Present means a key is configured, not that provider calls work.

Active execution and pending action reviews/receipts can block saving a model change. Browsing cached choices stays available. Open questions and historical interrupted/Unknown outcomes do not require acknowledgement or block a model change. Resolve any pending action in its originating conversation. A blocked source does not establish that the model provider is unavailable.

Change avatar in the bot’s settings. Choose one of 12 bundled Open Bot Avatar characters or a registered library design, a colour or automatic colour, and whether to animate. Save applies appearance only; Cancel discards the draft and Reset restores the generated default. Limited devices can change appearance. The Agents sidebar always shows static avatars. Animate avatar enables idle motion in the chat header and other agent views. Message rows have no avatars; agent bubbles follow avatar colour. Turning it off stops motion everywhere. System reduced motion always wins; pointer following and turning are preview-only. Waiting uses a neutral face with explicit approval/input indicators. A completion expression is temporary feedback, not evidence of an external action. Existing avatars may look different after this replacement; agent identity, history, memory and permissions are unchanged. The picker includes seven upstream characters and five generated additions: Book, Compass, Robot, Rocket and Telescope. Ask the bot to generate an avatar. With the generation skill and avatar tools available, it validates the design and shows a preview in chat, then can add that exact design to the shared avatar library when requested. Full access adds the validated draft without an Inbox approval. Read Only and Workspace Write require Inbox review; Keep preview (Ignore) leaves only the chat preview. Registered designs appear in every agent’s picker without a rebuild. Selecting one remains a separate appearance save. JSON import/export controls are unavailable. See docs/notes/avatars/README.md.

Model and reasoning use the same shared field sizing and focus treatment in creation, agent settings and room routing. The model picker groups choices by provider; agent Settings keeps its explicit Save action.

Full access devices also have icon-only model and effort/thinking menus in the chat composer: the CPU icon opens model choices and the brain icon opens reasoning choices. Hover or keyboard focus shows the current selection; the menus show full option names and checked values. The same grouped shadcn menu is used in chat, agent settings, agent creation and room routing, with provider headings and a checkmark on the selected item. A selection saves the addressed agent’s configuration across its chats; it is not a per-message override or proof of the returned model. Discovery is loaded when a control opens. Sending waits during changes or an unresolved configuration draft. Successful model changes show the updated selection without a confirmation line or toast; a brief icon loading state indicates work in progress. A failed/uncertain save keeps the draft and offers explicit Reload model settings, without automatic write retries. Numeric budgets remain in Settings. See [composer model controls](../notes/oa-335-model-configuration.md#composer-model-controls-oa-404).

In agent Settings, Model and reasoning keeps the model/effort selectors and Save model configuration first. Expand Model diagnostics for saved and requested settings plus session/returned reports, timestamps, room/provider/turn/session/configuration identities and stale-report labels. A previous-configuration report remains stale after a new save; it is not evidence of the new selection. No diagnostics are added to ordinary chat menus or their footers. Settings, Models lists provider/adapter configuration; select models through agent Settings or the chat composer.

Settings → Models → Dictation selects the installation transcription provider and model. Owner/Full access is required to save it. OpenAI reuses the daemon’s OPENAI_API_KEY; subscription sign-in does not supply this credential. It is independent of each agent’s chat model. Off is the default; provider audio processing incurs API usage. See [composer dictation](../notes/composer-dictation.md) for supported targets, setup and limits.

For local speech-to-text, install an audio-capable Ollama model on the daemon host, use Settings → Models → Refresh models, then select it under Dictation. OpenAg uses reported audio capability from that refresh. The local endpoint must be on loopback; no OpenAI key is used for local transcription.

Chat, routing, dictation and hosted image delivery use shared cached model capabilities.
Model names alone do not establish support. Refresh models in Settings → Models
updates the choices; models with missing capability metadata are not offered for
new task selections. Existing saved targets are retained without automatic replacement.
Recorded-file transcription choices exclude realtime-only models. See
[model selection and capability discovery](../notes/model-picker.md) and
[dictation](../notes/composer-dictation.md) for setup, compatibility and failure behavior.

An old failed or cancelled task remains in history; there is no Mark as reviewed workflow. Continuing the conversation does not confirm or replay the old tool call. See [Work and ordinary chat](work.md).
