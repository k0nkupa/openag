# Composio (optional connection)

OpenAg can connect to Composio's hosted MCP service with browser OAuth. No `COMPOSIO_API_KEY`, local App installation or Composio CLI is required for this path. Composio stays optional; direct first-party connections, Apps and administrator-managed MCP servers remain independent.

## Installation setup

OpenAg generates and preserves its connector encryption key automatically. Users do not enter an owner token, connector key or Composio API key to connect. Owner access and provider consent remain separate: use a Full access device for sign-in.

Choose **Connect Composio**, sign in in the new tab, and OpenAg checks the result in the original desk. There is no sign-in-address form. Your HTTP Tailscale desk can stay where it is; browser device credentials do not move to the callback origin. Allow sign-in pop-ups if the browser blocks the new tab. **Cancel sign-in** cancels the attempt without removing an existing connection.

The daemon selects a callback route before consent starts and pins it to that attempt:

- **Hosted relay (opt-in):** when the operator sets `OPENAG_SIGNIN_RELAY_URL`, that HTTPS relay (source in `apps/signin-relay`) receives a short-lived authorization response. The daemon retrieves it through an outbound request with a separate random read credential. No incoming route, custom domain or HTTPS certificate is required on the OpenAg computer. The relay receives the OAuth state/code (or denial), never the PKCE verifier, owner/device credentials, provider access/refresh tokens, service-account grants or tool data. It encrypts the callback to an ephemeral daemon public key before database storage, keeps that ciphertext for at most five minutes, erases it on completion/cancellation, and never redirects to a supplied desk address. This introduces an operator-run cloud dependency for sign-in only. There is no built-in relay; without one, sign-in uses the private Tailscale callback.
- **Private Tailscale:** if hosted preparation fails before consent and the browser uses the installation's tailnet/local address, OpenAg can discover the host's Tailscale DNS name and create or reuse a private HTTPS `/composio-connect` path through Serve. Existing routes remain intact; conflicts, public Funnel on that listener, unavailable HTTPS permissions or a signed-out Tailscale client produce an actionable failure. OpenAg never enables Funnel or resets Serve. The browser must be connected to the tailnet. A private route is not a fallback after consent has started.

The callback tab only reports that a response was received and attempts to close. The original authenticated desk reads its own attempt, and the daemon checks the initiating device's current Full access before exchanging the code and before saving. Another Full device cannot read or finish that attempt. A response at the callback does not grant device login or tool authority. Revocation, downgrade, disconnect, cancellation or expiry prevents late credential writes. Daemon restart cancels in-memory attempts; saved connections survive. A failed or cancelled reconnect preserves existing ciphertext and client registration. Temporary relay/status-read failures retry within the same attempt deadline; malformed responses and terminal failures stop it. Token exchanges are never retried by the polling loop.

## Operator configuration and compatibility

Ordinary users enter no addresses or keys. Operators can set `OPENAG_SIGNIN_ROUTE=auto|hosted|tailscale` (`auto` is the default) and `OPENAG_SIGNIN_RELAY_URL` to an HTTPS relay origin. There is no default relay: `auto` uses the relay only when `OPENAG_SIGNIN_RELAY_URL` is set, otherwise the private Tailscale callback; `hosted` without a relay URL is refused. Deploy your own relay from `apps/signin-relay` if you need one: see [deploying the sign-in relay](signin-relay.md). See [relay operation](notes/one-click-composio.md).

Explicit `OPENAG_COMPOSIO_REDIRECT_URI` / `OPENAG_PUBLIC_URL` overrides retain priority for operator-managed callbacks. They must agree when both are set. A saved explicit `connectorSignIn.callbackOrigin` also retains priority; its settings and the authenticated completion endpoint remain for compatibility, but the normal desk no longer edits them. New managed attempts do not require desk-origin approval because there is no return URL: the original desk remains open and authenticates its own status requests. Browser/Host/forwarded input never chooses the provider callback origin. A loopback operator override is usable only by a browser on that loopback origin.

Changing the selected route can require fresh client registration at the next explicit Connect. Existing access stays active until that attempt succeeds. Refresh retains the original known registration callback; it does not silently move a working connection. The installer preserves operator overrides and the original connector key. Google consent and the legacy API-key bridge are unchanged.

Direct callbacks at `GET /composio-connect` remain server-owned, bounded and protected by single-use pending state/PKCE. Managed callbacks return a static close-tab page with no codes or credentials. Legacy attempts can still return a non-secret display hint to a previously approved desk; the desk reads authoritative status and removes that hint from history. Neither route treats a display hint as proof of a connection.

## Connect and use

In **App library**, open **Composio**, then choose **Connect Composio** from a Full access device. Use the paired Full device that starts the attempt; a callback browser does not gain that device’s authority. Sign in and return to OpenAg. **Connected** means the MCP connection and tool discovery succeeded; saved account credentials alone do not establish a working tool connection. Opening the card and reading status never starts sign-in or probes the provider.

Connecting OpenAg to Composio and connecting another service through Composio are separate grants. Services such as Gmail or GitHub may need their own consent. Composio supplies tools to request those connection links; it manages the upstream accounts. Tool arguments and results pass through Composio and can reach the selected bot's model provider. Avoid sending credentials or private data that is not needed for the task.

The fixed managed server is `composio-connect`, exposed as `mcp.composio-connect.<tool>`. Both API/Ollama and ACP bots use the same daemon policy/approval path. Remote hints cannot lower tool classes. The reviewed Connect contracts classify `COMPOSIO_SEARCH_TOOLS` and `COMPOSIO_SEARCH_SKILLS` as Search, and `COMPOSIO_GET_TOOL_SCHEMAS` and `COMPOSIO_USE_SKILL` as Read. They follow the bot’s corresponding permissions. Connection management/waits, execution, proxy, shell/workbench, skill changes and feedback remain `act-external`, Ask by default, and cannot be Auto. New names and the same names on another server retain unknown-tool treatment. Unattended turns without approval permission cannot run those external tools. Results are bounded, redacted and labelled untrusted. Connecting an account grants no execution permission.

The shared [MCP classification and completion rules](notes/mcp.md#trusted-classification-and-completion-oa-379) apply. Reviewed tool/skill discovery is Search; schema retrieval and skill loading are Read. Execution, connection/wait, proxy, shell/workbench, skill changes, feedback and unknown tools retain external-action approval. A completed discovery response can report connection status without proving mailbox access. For external actions, MCP transport success does not prove an external effect: without authoritative confirmation, the receipt remains **Unknown** and the bot must inspect its retained evidence and target before repeating an action. This OAuth feature does not add provider-specific completion/readback adapters. It also does not guarantee that the default bot can complete every upstream service's connection workflow.

## Reconnect, disconnect and failures

**Reconnect Composio** starts an explicit new sign-in. OAuth state is device-bound, single-use, valid for five minutes, capped at five pending flows, and invalidated by disconnect or connection changes. Revoking its initiating device invalidates pending sign-in, including an exchange already in flight. Provider denial makes no local account change. Closing before a response leaves an expiring attempt; if the provider response may already have arrived, check connection status before retrying.

Access tokens refresh on demand through a single shared refresh. Invalid access/refresh credentials require reconnecting; background work never opens the browser. A refresh failure conservatively withholds tools until reconnect. Provider failures and timeouts produce short errors; requests do not follow redirects to other endpoints. Tool requests never automatically replay after a 401/403, refresh failure or uncertain response.

**Disconnect Composio** clears local credentials and tool access, aborts outstanding requests and closes cached connections. It does not delete connected services at Composio. The provider metadata checked for this feature did not advertise token revocation, so OpenAg reports provider revocation as unconfirmed. Review your Composio account to revoke the provider grant. A late exchange or refresh cannot restore disconnected access.

## Credential storage and backup

Credentials and client registration are AES-256-GCM encrypted in `$OPENAG_DATA/connector-composio.enc` (mode 600). The separate key is saved privately in `$OPENAG_DATA/.connectors/key` (64 hex characters, mode 600 in a mode-700 directory), independently of the owner credential. An existing key override is imported without changing its bytes; later starts can reuse the saved key without an environment variable. A conflicting supplied key is refused. During first key import, a healthy saved connection validates its own encrypted record without depending on another connector’s damaged or unsafe record. If the caller has no saved record yet, existing peer credentials still validate the original key before it is published. This keeps a wrong key from being saved before a legacy connection can reject it. Files with unsafe permissions, ownership, hardlinks or symlinks are refused. Tokens are registered with the redactor, never returned by connection/status APIs and never placed in SQLite, `mcp.json`, browser storage or bot environments. Codes and PKCE verifiers are memory-only.

Like Google credentials, this file is outside SQLite backups. Include the encrypted files and the private `.connectors/` directory in a secured host backup. SQLite backups do not include either. Missing/corrupt original key state, unsafe permissions or conflicting keys need recovery on the OpenAg computer; restore the matching key and ciphertext. OpenAg never generates a replacement behind existing encrypted credentials. Interrupted publication recovers a sole validated staging key, or an empty directory before any key was used. The private initialization marker prevents a missing used key from being regenerated. Ambiguous/unsafe staging state requires recovery. A corrupt or unsafe file needs administrator attention; OpenAg does not overwrite it. Same-user trusted local code is not sandboxed by encryption.

## Existing API-key bridge

An already installed `examples/apps/composio/` remains available as **Composio bridge (legacy API key)**. Its tools, environment requirement and owner-reviewed folder are unchanged. No migration, enable/disable action, credential deletion or account adoption occurs automatically. The new connection has a separate tool namespace. Owners should deliberately choose a path to avoid accidental duplicate actions.

The legacy bridge uses the REST API at `https://backend.composio.dev/api/v3.1`, with `x-api-key`. Its two tools are `app_composio_find_tools` and `app_composio_run_tool`, both `act-external`. Existing installations can continue using it.

## Evidence and limits

See [implementation and verification notes](notes/composio-connect.md). Source/controlled acceptance is separate from deployment and real-provider acceptance. The source implementation and controlled checks changed no live Composio account, upstream service or installed daemon. The subsequently owner-authorized 2 November 2026 deployment is recorded separately in deployment evidence; it does not establish OAuth or upstream-service acceptance.

Shared remote invocation, server-input review, catalogue validation and evidence behavior are documented in [MCP lifecycle](notes/mcp-lifecycle.md). These rules apply across integrations; answering server input does not approve another tool or confirm a write. Task-only tools remain unavailable, and interrupted calls are never replayed automatically.

Known Connect tool results are checked for explicit provider-envelope failures before generic output caps. A partial batch or upstream proxy HTTP error is not a completed read; a returned external call remains Unknown. The reviewed declaration and evidence rules are documented in [MCP classification](notes/mcp.md#reviewed-composio-contracts-and-provider-envelopes-oa-390).

## Shared integration details

Every App library entry uses IntegrationDetails: one name, machine and semantic status in the fixed header; Overview, Tools and optional Local setup tabs; one approval reminder in the footer. Overview contains provider actions and metadata. Composio has icon-labelled Connect/Reconnect and a destructive-outline Disconnect action, without a repeated connection heading or Connected line. Disconnect still requires confirmation and only removes local access; provider revocation is unconfirmed. The privacy explanation appears once on Overview. Tools are collapsed rows with their exact names and classes; expand for untrusted descriptions. Switching tabs retains pending sign-in, confirmation and local-setup state. Provider-specific components continue to own action validation and API calls.
