# Derive a connector package's launch command instead of storing it

A package pin in `mcp.json` stored the exact node path and daemon root, and the daemon refused the connector unless they matched its own, so every deploy from a new release folder or node binary turned a healthy connector into "Failed". The pin now identifies only the connector id and package digest; the daemon derives the launch command itself and ignores any command, args or env stored for a pinned entry. We chose this over re-running setup after each deploy (setup refused to touch a mismatched entry, so it could not repair one) and over a fixed deploy path (fragile and unenforced). Code integrity is still enforced by the digest, and configuration can no longer name a different program, arguments or environment for a pinned connector.
