## State and access

Available means catalogued but absent. Needs setup means review/environment setup is incomplete. Ready for a local App means the reviewed folder, interpreter and required environment are available; it does not verify provider credentials or account access. Connected for MCP requires actual handshake and tool discovery. Paused App state records the explicitly disabled folder digest; it never preserves an execution approval. Old disabled Apps remain Needs setup because their prior intent cannot be inferred. Paused remains explicit alongside missing dependencies. Inventory refresh prunes pause records for missing, invalid or changed folders. Missing interpreters are Unavailable; invalid folders, refused configuration and failed MCP connections remain Failed with their actual reason.

Browsing refreshes the known App folders and tool registry together without discovering new folders, executing installed code, initiating provider connections or granting approval. A known folder that changes or disappears loses its obsolete approval immediately, including on status reads; restoring its old files does not silently enable it again. Apps still require fresh whole-folder hash approval; changed code fails a stale enable request. App reload/enable/disable and MCP reload require owner-level access, preserving full devices' existing owner equivalence and limited-device refusals. WebRTC admits the read-only library endpoint with the existing bounded 2 MiB chunked-response budget, checked with a 400-tool inventory above the default 256 KiB cap; reload/enable/disable remain outside its allow-list. MCP configuration stays administrator-owned and unwritable over HTTP.

Requirements expose environment names only. The shared inventory omits App command arguments for all clients. Raw commands are fetched only by a fresh owner-authorised `GET /apps/:id/review`; limited-device `/apps` listings omit them too, since unknown literal arguments may contain private URLs or credentials. MCP command, arguments, header values, URLs and resolved environment values are absent from the projection. The library response is redacted; descriptions render as React text and tool results keep their existing untrusted wrappers. Declared Apps tools are separate from discovered MCP tools. Neither enabling nor listing changes any bot approval modes; installed code is not sandboxed by those modes.

Actual installation/setup, OAuth, downloads, account health checks, destructive removal and the reviewed Add-to-machine workflow remain OA-328. No provider account or live installation was used during this ticket's controlled verification.
