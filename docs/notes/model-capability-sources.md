# Capability discovery source coverage — 4 November 2026

Research and unauthenticated metadata reads only. No inference, adapter launch,
installation, settings or service changes were made.

## Usable maintained feed

`https://models.dev/experimental/v2.0/api.json` returned HTTP 200 with 10,394,660
UTF-8 bytes during this investigation. It is a provider-ID map; each provider has
a `models` map keyed by the exact provider model ID. Records include `id`, `type`,
`modalities.input`, `modalities.output`, `capabilities` and `api` protocol entries.
The endpoint is implemented by the upstream server and generated by its website
build. [Server source](https://github.com/anomalyco/models.dev/blob/dev/packages/web/src/server.ts),
[build source](https://github.com/anomalyco/models.dev/blob/dev/packages/web/script/build.ts).

The ordinary v1 `api.json` and `catalog.json` do not provide equivalent coverage.
The current transcription definitions are `v2_only`; even the inspected v1
`type=all` response omitted them. Use the v2 endpoint, not a name-based fallback.
The endpoint is explicitly experimental: validate a small consumed schema, bound
response size (16 MiB currently fits), persist last-good data and do not interpret
a parse/network failure as a successful empty inventory.

## Integration rules

- Match exact provider/model IDs. Keep provider/account inventory separate from
  published capability metadata. Missing metadata remains unknown.
- Prefer authoritative provider capability fields when available; use the public
  feed to fill gaps. Do not turn absence from a finite catalogue into a provider
  claim that the model cannot do the task.
- Check the application's protocol and payload compatibility as well as input and
  output modalities. Audio input plus text output does not imply transcription.
- Never execute downloaded SDK identifiers or let feed `base_url`, headers or
  other connection configuration override the daemon's reviewed transports.
- Fetch this public endpoint without provider credentials. Refresh metadata only
  through existing manual/scheduled refresh; cached menu reads remain passive.
- Ollama's file endpoint accepts WAV and streams output from an uploaded file.
  It does not document live microphone append input. Keep that distinction when
  interpreting the local model's `audio` capability. [Ollama compatibility](https://docs.ollama.com/api/openai-compatibility).

The installed Mastra helpers remain useful for reasoning controls, but its
attachment helper is a provider-wide model-ID list that returns false when a
known provider does not list the model. That negative is catalogue absence, not
fresh provider evidence. Its declarations expose no equivalent transcription
protocol catalogue. This was checked in installed Mastra 1.79.0 declarations.

Source coverage is sufficient to begin implementation with the v2 feed plus
provider-specific Ollama and Typesafe discovery. Actual account access, inference
acceptance and local microphone quality remain unverified by this research.

Ollama defaults an omitted model tag to `latest`; catalogue lookup must preserve
this equivalence for existing untagged selections. [Official model-name conventions](https://github.com/ollama/ollama/blob/main/docs/api.md#model-names).
