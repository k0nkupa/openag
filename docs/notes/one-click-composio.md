# OA-367 one-click Composio sign-in

Approved 3 November 2026: remove normal sign-in address entry; provide an OpenAg-hosted callback relay and automatic private Tailscale callback setup. Implementation is local only. No worker, DNS, Serve, OAuth client or provider-account deployment/change is authorized by this implementation approval.

## Flow and ownership

Connect opens an empty tab synchronously from the click so mobile browsers can allow it. The Full-authenticated start request selects a callback before provider consent. The original desk stays open and owns one bounded status loop; the callback tab never gets the desk credential. The daemon owns PKCE, client registration, token exchange and the encrypted account store. Another device cannot poll/cancel the attempt, even when it has Full access. Current access is checked before exchange and saving. Cancel/revoke/disconnect/expiry stops late writes. Pending attempts intentionally do not survive daemon restart; existing encrypted access does.

Normal `auto` mode prepares a hosted mailbox first when `OPENAG_SIGNIN_RELAY_URL` is set (there is no built-in relay), and prepares a private Tailscale callback otherwise or if hosted preparation fails before consent. Once the provider URL has been issued, an attempt cannot switch route. Explicit operator `hosted` or `tailscale` mode prevents fallback. Legacy explicit callback environment overrides and a saved explicit callback origin retain priority; old stored desk-address settings remain a compatibility API, not part of ordinary sign-in. Temporary relay/status-read outages retry within the pinned attempt deadline; malformed responses are terminal. Polling never retries token exchange.

## Hosted relay

`apps/signin-relay` is a Cloudflare Worker with one SQLite-backed Durable Object per random state. OpenAg ships no default endpoint: an operator deploys the Worker to their own account and sets `OPENAG_SIGNIN_RELAY_URL`. The repository supplies source and a deployment dry-run only.

The daemon creates a five-minute session with a state, a fresh P-256 public key and SHA-256 digest of an independent random read credential. The private key stays only in the in-memory daemon attempt. Before persisting a callback, the Worker uses fresh ephemeral P-256 ECDH, HKDF-SHA256 and AES-256-GCM (96-bit random IV), binding the protocol version and state as authenticated context. Only the daemon can decrypt the stored envelope; points, nonce and ciphertext sizes are validated. Raw codes remain memory-only. A modified envelope fails authentication before exchange. The provider callback can submit its bounded state/code or error once. Only the outbound daemon holding the read credential can retrieve the result or close the session. Successful and cancelled sessions keep a tombstone until their original expiry, then an alarm deletes storage. Codes are removed when the daemon closes a session; if cleanup cannot reach the service they expire. Retrieval can repeat until cleanup, so a lost network response does not lose the callback; the daemon's consumed/exchanging state prevents another exchange. The relay never exchanges tokens, never receives the PKCE verifier or device/owner credentials, and never stores user return origins. Its completion page contains no callback values or external assets, clears the query from history and attempts to close the tab. It does not claim provider connection success.

Every callback/result/session request has platform per-IP and shared rate limits before any Durable Object dispatch; session creation has a tighter additional budget. A regression check first reproduced unthrottled random-state probes, then verified HTTP 429 after the pre-dispatch limit. These limits are per Cloudflare location, not an exact worldwide quota. Body/query/field sizes are capped. Unknown sessions, bad credentials, duplicates and malformed callbacks return generic errors. Code and state are not application-logged; invocation logging/tracing is disabled because URLs carry callbacks. Operators must preserve that exclusion when adding account-level logging. DO alarms remove expired records; runtime response checks enforce expiry even if cleanup is delayed.

No user secret is needed to configure the relay. An operator sets `OPENAG_SIGNIN_RELAY_URL` (HTTPS origin only); `OPENAG_SIGNIN_ROUTE=hosted` without it is refused. Users do not configure it in the desk. Running a different relay introduces a different sign-in service operator and trust boundary.

## Private Tailscale callback

The daemon reads `tailscale status --json` and `tailscale serve status --json` using bounded argv-only CLI calls and a minimal child environment. It derives the DNS name from the host's own Tailscale state, not the browser/Host/forwarded headers. Automatic private fallback accepts only the installation's known tailnet hostname/IP or local browser origin. An unrelated Cloudflare desk must use the hosted relay or an explicit reachable operator callback.

Only HTTPS `/composio-connect` is added, forwarding to the daemon's actual loopback port/path. A matching existing route is reused. An incompatible route, TCP listener or Funnel on that listener is refused. There is no reset, public Funnel, shell interpolation, deletion of another route or generic ingress framework. The route persists in Tailscale and can be reused after restart. Tailnet HTTPS/Serve permissions are prerequisites; any Tailscale administrator enablement remains an operator action. Saving no form is required, but OpenAg cannot silently supply permissions it does not have.

## Verification and release limits

The first standalone assertion failed against the old implementation because an HTTP desk still required address setup. It passed after managed routing was wired. Current Worker/SDK/gateway checks use Miniflare's real workerd runtime, temporary SQLite/encrypted files and controlled provider endpoints. Tailscale commands use the host-command seam: no real network configuration is written.

Workspace build, relay types/deployment dry-run, controlled Worker/SDK/gateway/private-route checks, legacy/remote callbacks, desk/onboarding and bot-knowledge delivery passed. The actual browser check clicked the Connect/Reconnect button, retained the original HTTP desk/device session, proved token-free HTTPS callback storage, and showed completion for both routes. It uses a controlled provider-navigation adapter (no real Composio page), local self-signed TLS and certificate bypass only in that disposable browser process. Private CLI writes are simulated at the host-command boundary, not executed. All planned compatibility and delivered-knowledge checks passed. Standards review identified missing public-probe limits and insufficient polling headroom; both are fixed and the 602-probe/normal-envelope regression passed in the actual Worker runtime. Spec review requested historical-baseline and product-note corrections, now applied. A further standards pass identified that raw callback codes must not reach the relay database; callbacks are now encrypted to an ephemeral daemon key before storage. The public response regression first failed against raw callback storage, then passed for the encrypted envelope with both browser paths. The first built-in Codex review requested saved-callback priority and transient status-read recovery; both are fixed with production-factory and real React regressions. The next review reproduced overlapping status reads overwriting a completed result and API-wrapped network failures (status 0) escaping retry. Mailbox reads are now serialized per attempt, terminal outcomes cannot be overwritten by stale readers, and status-0 errors retry. Both regressions first failed through the actual Worker/gateway and real createApi/React seams. A further review found stalled browser fetches could defeat Cancel/deadline. Signals now propagate through whoami/start, status reads, legacy owner retry and bounded cleanup; status waits are capped by the remaining attempt lifetime, and nonessential inventory refresh cannot hold the busy state. Real createApi/React stalled-read checks failed against the pre-fix revision and now pass for explicit cancellation and a short attempt deadline. Final Standards/Spec follow-ups and built-in Codex review passed with no remaining actionable findings. The reviewed scope is `7596c94...HEAD`; only the completion log changed afterward. Parent-controlled browser/SDK/gateway/Worker, compatibility, owner-access and packaged bot-knowledge checks passed. No unit/Jest/Vitest suites are allowed. Live relay deployment, provider registration policy, physical-phone pop-up behavior, certificate permissions and real Tailscale round trips remain separate acceptance.
