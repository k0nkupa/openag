# Standing responsibilities and scoped investigations

OA-368 implements the first synthetic loop, not live Outlook monitoring or a new task engine. The normal daemon constructs Responsibilities without a source adapter; readiness is source unavailable and enabling is refused. There is no HTTP event simulation route, environment test switch, account connection, credential store or production synthetic source. Controlled acceptance injects a synthetic adapter privately. A real source requires its own reviewed adapter and account authority.

## Owner controls and domain

Automations → Standing responsibilities shows source readiness and owner configuration/history. The owner creates a paused agreement, reviews its exact sender/topic, source binding/resource, bot, question and destination, then explicitly enables the reviewed revision. Management routes POST /responsibilities and PUT /responsibilities/:id are owner/full-device only. Updates require baseRevision; stale edits are refused. Saving an edit pauses it for review. GET /responsibilities and /responsibilities/:id/history use normal authenticated desk reads. This grants no new source authority to a bot or event. WebRTC’s existing path allow-list is unchanged: these controls/history use authenticated HTTP over the normal LAN/Tailscale route. Phone-width acceptance does not establish physical-device or RTC acceptance. There are no new bot management tools.

The trusted private observation path accepts only the enabled binding/resources. Exact normalized sender plus configured subject topic words is the first relevance rule. Unrelated input creates no investigation; an empty topic observation remains uncertain. This is not a learned relevance classifier. Event identity is responsibility/binding/source event ID/version; conflicting duplicate content never overwrites the first observation. The first conflict retains a bounded timestamp and audit event, visible as a source-conflict warning in investigation history. A new responsibility revision does not make an old event new. No issue merging or cross-source search is inferred.

## Scope and limits

Only API/Ollama support this investigation entry. ACP is blocked before execution, including if runtime changes while queued. Ordinary ACP remains unchanged. One active and at most one queued observation per responsibility bounds intake; overflow is refused without acknowledging it as processed. At most 50 responsibility configurations are retained. Events are capped at 8 KiB; source and event evidence older than 24 hours or future-dated is not accepted as current.

The trusted profile gives 12 model steps, 24 executor starts and a five-minute deadline. The controlled fixture can shorten that internal deadline but cannot increase it. Only investigation_read is offered; account/resource scope comes from the daemon rather than tool arguments. The runner's authorization gate and the executor both check current revision/readiness/cancellation. The policy must already permit Auto read; Ask or Deny is never overridden. Generic filesystem, browser, shell, external actions, secrets, memory writes, request_input, save_result, Work creation and delegation are unavailable. Existing isolated/offline watcher behavior is unchanged.

Investigations omit bot-wide memory, vector recall, skills, unrelated history and attachments. Event and source output remain untrusted context. Reads retain at most 24 evidence excerpts, each at most 2 KiB and redacted. Reports are bounded at 32 KiB. Proposed evidence IDs must resolve to retained authorized reads. A complete turn alone cannot certify business completion or the correctness of natural-language conclusions; source state and uncertainty stay inspectable. Missing access/record and failed/refused/stale/oversized reads produce incomplete results with known reasons. A curated adapter can flag contradictory records; the daemon forces an incomplete conflicting-evidence reason and explicit uncertainty, retaining the flagged evidence even if the model cites a different subset. It does not pretend to detect arbitrary semantic contradictions in free text. A final report can include one owner question without creating an approval or Work item.

## Results and delivery

Raw investigation execution rooms are daemon-private: room APIs and WebSocket projections never expose their source/tool/model ledger events. Owner inspection uses the current-scope history/result projections; RTC already excludes hidden rooms. A valid partial report is parsed separately from runner diagnostics and remains an Incomplete proposed result.

Investigation results have genuine investigation/turn provenance with no invented tool call and no Work. Settlement is daemon-only; normal save_result still requires its real reviewed tool call. Investigation artifacts are immutable; an approved interactive edit must save a separate conversation artifact. Legacy results retain their IDs, versions, scope, bytes and paging sequence. Investigation artifacts do not consume the interactive conversation/Work result quota. Proposed findings and the unsent reply display as readable text, with evidence references/times. They are not external drafts or verified financial actions.

Settlement stores result and delivery intent in one transaction. Delivery then rechecks current scope. A stable investigation/result-version key commits wake decision, local ping/digest result reference and audit together. The morning brief carries those result identities as desk links and rechecks source visibility before releasing them. Paused/revoked scope items stay withheld. Artifact storage uses the reviewed result room; proactive notices still follow the owner’s existing global delivery-room setting. Restart reconciles a pending delivery without rerunning its model or reads; repeated keyed decisions reuse retained evidence, including after the temporary dedupe window. Existing unkeyed callers, active hours, urgency, dedupe, budget and destination selection remain intact. External notification callbacks run after the local commit and are not replayed on duplicate recovery. A crash between commit and callback can lose a push; no exactly-once device receipt is claimed.

Pause/edit invalidates queued/active old-scope attempts and signals cancellation. Revocation fences subsequent reads and publication; a late source response cannot append evidence or publish. Result/content reads require the current permitted revision and source; unavailable/paused scopes show retained status metadata without exposing evidence or result content. Previously delivered notices cannot be recalled. Restart marks admitted unfinished investigations Interrupted and never replays them. Never-started queued observations receive a first admission only after current scope/freshness/runtime checks; interrupted investigation continuation is unavailable.

Source and model transports in scripts/verify-secretary.mjs are synthetic. They establish persistence, scope and UI behavior, not real-model relevance, real source consent, financial correctness, physical-phone receipt or live readiness. Unit/Jest/Vitest, live providers and deployment are excluded.
