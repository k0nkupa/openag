# Agent requests

Owner approved the domain model and implementation plan on 4 November 2026. This note describes source behavior. Acceptance is recorded below separately from deployment; the installed service is unchanged by this branch.

## Two entry points

- In an ordinary interactive conversation, an eligible coordinator uses `agent_list` for passive discovery and `agent_consult` for a bounded question to an existing agent. The tool returns admission, not findings. After the initiating turn ends and releases its lock, the specialist runs and the coordinator receives one correlated findings message for synthesis in the original conversation.
- In a direct chat, the owner's explicit `@handle` addresses a guest. The guest answers under its own identity in that same chat. No room membership, direct-chat identity, default bot or proactive destination changes. Multiple mentions address each distinct target, up to three. A conversation admits at most 50 outstanding requests. The bounded status projection preserves all outstanding requests; the desk limits only settled history to the latest three. Mentioning the permanent counterpart uses its existing path. `@everyone` stays local to current members; it is not offered as an installation-wide option. Named rooms and other ingress routes retain member-only addressing.

Display names can repeat; stable handles identify recipients. Unknown handles fail explicitly instead of falling back to the lead. Missing runtimes and busy recipients are refused. Busy means admitted activity or pending approvals, open questions, active Work or pending action receipts. No new busy queue or ephemeral agents are introduced.

## Request and context

The daemon records invocation identity, originating message/conversation/turn, initiator, recipient, selected question/context, permission ancestors, execution outcome and reply delivery separately. Admission is transactional. Reusing an invocation with changed content fails; matching duplicates read the retained result instead of starting another run. This is local duplicate admission protection, not exactly-once remote execution.

Questions have an 8,000-character limit; explicit selected context has a 16,000-character limit. Both are redacted. Specialist findings are capped at 16,000 characters with an explicit shortening marker. The existing runtime projection records additional omissions. These are JavaScript string-length limits, not token estimates. Requests have no fixed overall deadline for dispatch, execution or synthesis. A service restart interrupts requests without replaying them. Individual model and tool operations can still have their own limits. Pausing the initiating turn for input cancels its admitted consultations instead of leaving the recipient reserved.

Specialists execute in daemon-private request contexts through the normal runner and central tool gate. There is no automatic source history, recipient DM history, memory-head or vector-recall sharing, and specialist request turns are not vector-indexed. The recipient keeps its identity, operating instructions and assigned skills. Native ACP effects remain disabled. A fresh private recipient session is deliberate; the initiating agent's unchanged conversation session remains reusable. A new guest exchange refreshes the affected cached ACP conversation once, so its next turn receives the authorized guest question and reply in bounded history.

Owner guest mentions include only that submitted message's attachments, loaded through the original bound upload references. Model consultations share explicit text context; they do not automatically forward attachments. Each addressed agent uses its own configured model. Existing attachment/model compatibility checks remain applicable.

Attributed guest replies and their originating request are available as bounded shared conversation history to the permanent counterpart. This does not make the guest a member or let it read earlier history. Tool output, excerpts and specialist findings remain data rather than operating rules or permission grants. The synthesis input is retained but not shown as another daemon chat bubble.

## Authority and outcomes

Only eligible interactive coordinators can initiate consultations. Unattended, isolated, offline, investigation, guest execution and synthesis turns cannot use agent_consult. Guest execution cannot create Work, request input, append memory or save artifacts directly. It returns proposed artifact content for the coordinator to save through the existing result tool in the original conversation. Legacy room delegation remains available; using explicit consultation suppresses additional output-parsed delegation in that turn.

A consultation initiated during existing Work retains that Work as its source. Cancelling it aborts specialist and synthesis execution; consultation never creates a new objective.

The recipient gets a normal permission session for its private request context. It starts from the owner-governed standing default and is intersected with the initiating session and ancestors. It never borrows permissions from an unrelated DM. Parent references retain exact IDs and revisions. Actionable specialist approvals, provider form/URL input requests and Unknown receipts are projected into the original conversation and Needs you, while underlying authority records retain their private execution scope. Revision changes cancel applicable descendants and expire pending reviews; effective workspace intersections can reduce filesystem execution to Read Only. Full access/Never never creates an explicit approval. A self-reference enforces the original revision without changing an otherwise identical ACP cache identity.

Execution records accepted, running, completed, incomplete, failed, cancelled, interrupted or expired separately from pending/delivered/failed reply delivery. A completed specialist turn means findings returned, not that a business operation succeeded. Action receipts remain authoritative. Unknown child receipts remain historical evidence without blocking later operations or sibling requests. Cancellation and deadline expiry cannot undo effects or clear Unknown.

GET /rooms/:id/agent-requests is a passive bounded projection with no-store; POST /rooms/:id/agent-requests/:requestId/cancel stops that request. Both use existing authenticated conversation access. The desk shows concise status, Cancel and receipt links. The coordinator can use agent_request_cancel to stop one or all of its active requests in that conversation, including when an earlier receipt is Unknown. Approval notifications use only the projected origin event, avoiding a duplicate notification for the private execution event. Provider input keeps the existing owner/Full-only response contract and never grants action permission. Owner/Full devices can open the existing Request details sheet through a scoped originating-request route; private room/turn reads stay refused. Hidden request room events, tools and full prompt traces are excluded from ordinary room HTTP and WebSocket streams and direct turn-manifest reads. Historical receipt reads remain available; the former inspection mutation is removed.

Synthesis retains its initiating Work-run provenance, including when the coordinator itself is a delegated agent. The synthesized findings, rather than the admission progress message, return through any existing delegation chain. Source Work uncertainty also fences specialist effects. Expired requests cannot start synthesis.

No admitted specialist execution or synthesis is automatically replayed after restart. Pending requests become interrupted, pending approvals expire, known results remain retained, and failed delivery is explicit. Late output cannot change a settled request or publish another final reply. Model-request retries inside one execution retain their existing rules; they are not permission to restart the specialist.

## Acceptance

Restart expires synthesis approvals; neither specialist execution nor synthesis resumes from a stale decision. Queued synthesis cancellation releases its dispatch without waiting for another turn. Shutdown and abrupt recovery preserve interrupted source Work.
- `node scripts/verify-agent-requests-acp.mjs --real` passed with installed Claude (`sonnet`) and Codex (`gpt-6.1-sol`). Later generic lifecycle/UI fixes were covered by the controlled regressions; the real adapter checkpoint was not repeated for those changes.
