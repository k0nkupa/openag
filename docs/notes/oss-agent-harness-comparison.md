# Open-source agent harness comparison

Researched 2 November 2026, Pacific/Auckland. Scope: source and official-document research for OpenAg's tool harness. This is a recommendation, not an implementation plan, deployment or runtime acceptance. No dependencies were installed and no applications, tests or providers were run.

## Recommendation

Keep OpenAg's daemon, authoritative policy gate, durable approvals and action receipts. Improve the contract around each tool: discovery, current availability, execution context, result evidence and recovery. The best immediate example is **nightly-labs/OpenBot's progressive discovery**, complemented by **CopilotKit's interaction lifecycle**, **OpenClaw's separation of offered and executable tools**, and **Letta Code's explicit unknown outcome on interrupted external calls**. A separate CopilotKit/OpenBot project contributes a useful app-access diagnostic pattern.

Start with an authoritative tool catalogue and actionable availability. Do not introduce a new agent loop, replace the current scheduler or adopt a framework solely for these patterns.

## What the projects actually do

### nightly-labs/OpenBot: progressive discovery and tool-specific guidance

Its catalogue is derived from original built-in definitions. It keeps a compact initial list of names and exposes search, describe and deferred call operations. Search returns full schemas for up to three strong matches, short descriptions for the remainder and relevant workflow guidance. This avoids spending one model step to search and another to obtain the best result's schema. The code explicitly distinguishes discovery visibility from execution ownership. [Catalogue, lines 9–48 and 119–213](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/tool-catalog.ts#L9-L48)

The deferred call resolves to the original namespace/tool before routing. Invalid envelopes are rejected; source-specific validation and dispatch remain necessary. However, some errors collapse to a generic localized invalid-request message. This is a useful discovery design, not an example of ideal error remediation. [Router, lines 343–373](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/openbot-tool-router.ts#L343-L373)

Detailed tool guidance is loaded with search/describe rather than duplicated throughout a large system prompt. Browser guidance distinguishes ordinary input, authentication, human takeover and partial input outcomes. In particular, partial or uncertain input calls require a fresh observation before continuing. Copy the pattern of attaching operational guidance to the actual tool, not its specific browser APIs or secret handling. [Guidance, lines 12–64](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/tool-guidance.ts#L12-L64)

Routines require self-contained instructions naming the service/tool, account, steps, reporting destination and when to stay silent. The scheduler uses one derived due-time timer, explicit needs-attention transitions and occurrence-based enqueue keys. The mailbox idempotency helper concerns queued messages, not exactly-once execution at an external provider. [Routine schema, lines 69–76](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/routine-tool-schema.ts#L69-L76), [scheduler, lines 142–149](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/routine-scheduler.ts#L142-L149), [enqueue key, lines 1017–1027](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/routine-scheduler.ts#L1017-L1027), [tool-call key](https://github.com/nightly-labs/openbot/blob/ac99196e66fe8f9d426433aa5e79d6e999d1c818/src/backend/agent/tool-call-idempotency.ts#L4-L17).

### CopilotKit: explicit interaction lifecycle, not a universal policy engine

The v2 frontend tool hook re-registers tools when availability changes. Human-in-the-loop handling accepts an abort signal, rejects aborted interactions and removes listeners after settlement. Its renderer only offers the response callback during the executing phase; completed interactions retain their result without a live respond function. This is valuable for approval/question cards that must not re-execute after a rerender. [Frontend tool](https://github.com/CopilotKit/CopilotKit/blob/d168487e7a753a1527256c7e4c79344377f3d092/packages/react-core/src/v2/hooks/use-frontend-tool.tsx#L6-L56), [human-in-the-loop, lines 13–109](https://github.com/CopilotKit/CopilotKit/blob/d168487e7a753a1527256c7e4c79344377f3d092/packages/react-core/src/v2/hooks/use-human-in-the-loop.tsx#L13-L109).

Its context hook adds described JSON-serializable context and removes it when the hook changes/unmounts. This supports current UI context, but browser-provided context is information, not an authorization principal. [Context hook](https://github.com/CopilotKit/CopilotKit/blob/d168487e7a753a1527256c7e4c79344377f3d092/packages/react-core/src/v2/hooks/use-agent-context.tsx#L16-L44).

It would be inaccurate to call current CopilotKit only a chat component with no persistence: the inspected repository includes a runner interface with thread ownership checks, an in-memory runner and a SQLite runner with stored state. That still does not make a frontend HITL hook equivalent to OpenAg's durable server-side policy gate or prove restart-safe external actions. [Runner ownership contract](https://github.com/CopilotKit/CopilotKit/blob/d168487e7a753a1527256c7e4c79344377f3d092/packages/runtime/src/v2/runtime/runner/agent-runner.ts#L25-L71), [SQLite runner](https://github.com/CopilotKit/CopilotKit/blob/d168487e7a753a1527256c7e4c79344377f3d092/packages/sqlite-runner/src/sqlite-runner.ts#L67-L101).

### OpenClaw: discovery, execution and replay are distinct

Tool availability explicitly distinguishes stable offered definitions from tools callable during the current turn. Denied tools have argument-preparation callbacks removed and return a refusal result; a later catalogue projection cannot silently restore their execution rights. This is a good model for explaining unavailable capabilities without granting them. [Availability implementation](https://github.com/openclaw/openclaw/blob/0ce08d269ff82c9808c6c30a381742016cf2d4de/src/agents/agent-tool-availability.ts#L7-L142).

Replay safety uses source-owned metadata, not only a tool-name string. Duplicate/shadowed names fail closed when collecting replay-safe tools or side-effect owners. This supports per-tool recovery decisions; it is not permission to automatically retry all reads or arbitrary tools named like a safe core tool. [Replay safety](https://github.com/openclaw/openclaw/blob/0ce08d269ff82c9808c6c30a381742016cf2d4de/src/agents/tool-replay-safety.ts#L6-L104).

Current source differs from older heartbeat examples: its heartbeat document describes migrating monitors into ordinary automation jobs, and explicitly warns that heartbeat-specific deduplication and missing-route skipping were removed. Preserve OpenAg's existing wake filter; do not assume another project's newer architecture is a better notification policy. [Current heartbeat migration documentation](https://github.com/openclaw/openclaw/blob/0ce08d269ff82c9808c6c30a381742016cf2d4de/docs/gateway/heartbeat.md#L13-L84). The inspected cron facade delegates to locked operations; a full scheduler/restart audit was outside this comparison. [Cron service](https://github.com/openclaw/openclaw/blob/0ce08d269ff82c9808c6c30a381742016cf2d4de/src/cron/service.ts#L1-L39).

### Letta Code: scheduling ownership and honest interruption outcomes

Its cron scheduler claims a lease, feeds per-conversation queues and verifies lease ownership before firing. It deduplicates within a minute and exposes invalid stored cron expressions rather than leaving them silently inert. These are useful patterns if OpenAg ever permits multiple scheduler processes; a distributed lease is unnecessary while one daemon owns scheduling. [Scheduler overview](https://github.com/letta-ai/letta-code/blob/902822847baff7ec962bdf498f6b640c3fcf3603/src/cron/scheduler.ts#L1-L13), [tick/lease checks](https://github.com/letta-ai/letta-code/blob/902822847baff7ec962bdf498f6b640c3fcf3603/src/cron/scheduler.ts#L580-L618).

External tool cancellation stops the turn waiting, but the code explicitly says the remote operation may still finish. Its result tells the agent to inspect the destination before retrying a write. This closely matches OpenAg's existing unknown-outcome receipts and should be made consistent across all executors. It does not promise that abort rolls back a provider action. [External-tool interruption](https://github.com/letta-ai/letta-code/blob/902822847baff7ec962bdf498f6b640c3fcf3603/src/tools/external-tool-background.ts#L22-L78).

The tool definition helper keeps schema, description, model-facing form and implementation together, while serialization supports function-only backends. Borrow consistent metadata across runtimes rather than its particular model presets. [Tool definition](https://github.com/letta-ai/letta-code/blob/902822847baff7ec962bdf498f6b640c3fcf3603/src/tools/define-tool.ts#L14-L38), [model-facing forms](https://github.com/letta-ai/letta-code/blob/902822847baff7ec962bdf498f6b640c3fcf3603/src/tools/model-facing-tool.ts#L7-L67).

### Separate CopilotKit/OpenBot: explain access without changing it

Its read-only app-access tool reports distinct states such as ready, reconnect needed, disabled, not granted or owner-grantable. Inspection is actor-scoped and does not itself enable an app, grant access or file a request. The UI rechecks authorization before presenting its action. This is the strongest example for extending OpenAg's status tool with useful next steps. [App-access tool](https://github.com/CopilotKit/OpenBot/blob/c396a5f68c817043846f1ca3c2b42061ee73ceb5/server/src/plugins/app-access-tool.ts).

Plugin guidance derives from actual grants, and tool execution rechecks those grants. Handoff assertions bind actor/run/thread/agent identity and initiator. The useful distinction is **who has authority** versus **what triggered the run**; a single-process OpenAg daemon can carry trusted immutable context without copying a distributed signing system. Do not copy this project's documented allow-by-default startup policy. [Grant-derived guidance](https://github.com/CopilotKit/OpenBot/blob/c396a5f68c817043846f1ca3c2b42061ee73ceb5/server/src/plugins/tools.ts#L95-L110), [execution grant checks](https://github.com/CopilotKit/OpenBot/blob/c396a5f68c817043846f1ca3c2b42061ee73ceb5/server/src/plugins/tools.ts#L290-L340), [handoff identity](https://github.com/CopilotKit/OpenBot/blob/c396a5f68c817043846f1ca3c2b42061ee73ceb5/server/src/agents/handoff-signing.ts#L12-L24), [architecture](https://github.com/CopilotKit/OpenBot/blob/c396a5f68c817043846f1ca3c2b42061ee73ceb5/docs/architecture.md).

## OpenAg baseline: preserve what already exists

OpenAg already has validated ToolDefs, a central policy gate, persistent approvals, bot/room-scoped active-turn MCP tokens, strict unattended/isolated restrictions, action receipts with unknown outcomes and recovery, scheduler/heartbeat/wake filtering, and the new handbook/status tools. This work should improve those modules, not replace them. [Registry](../../apps/daemon/src/tools/registry.ts), [first-party registry](../../apps/daemon/src/tools/firstparty.ts), [policy](../../apps/daemon/src/policy.ts), [runner](../../apps/daemon/src/runtimes/runner.ts), [receipts](../../apps/daemon/src/action-receipts.ts), [scheduler](../../apps/daemon/src/scheduler.ts), [wake](../../apps/daemon/src/wake.ts), [status](../../apps/daemon/src/tools/status.ts).

There are already structured success/failure outcomes and GateOptions cancellation/deadline controls. The gaps are narrower: enabled() supplies no reason; tool output contracts and stable remediation codes are not shared; executor context lacks the gate's cancellation/deadline and a user/device principal; policy classification and ACP exposure use separate lists. Unify projections for daemon-owned tools while retaining explicit handling for native ACP aliases and administrator-classified external tools. API/Ollama offer external MCP definitions, while the inspected ACP server exposure is first-party plus enabled Apps. That parity difference must be intentional and visible, not hidden by a generic catalogue. [Registry](../../apps/daemon/src/tools/registry.ts), [turn interfaces](../../apps/daemon/src/runtimes/types.ts), [main wiring](../../apps/daemon/src/main.ts), [MCP server](../../apps/daemon/src/mcpserver.ts).

## Ranked changes for OpenAg's other tools

| Priority | Smallest useful change | Example and acceptance |
| --- | --- | --- |
| 1 | One authoritative tool catalogue with explainable availability | For a computer tool, return offered/callable, backend capability, policy mode, reason and authorized next step. Missing search credentials should say administrator setup required, not merely disappear. Do not expose token values or credential fragments. |
| 2 | Discovery and guidance from that catalogue | Keep the small core directly offered. Add bounded tool search/describe when MCP/App catalogues grow. Return schemas plus focused guidance for the best matches. A generic call wrapper must resolve the original target before its class, validation, approval and execution; never classify the wrapper as a safe read and execute a write behind it. |
| 3 | Stable errors and result evidence | Extend existing outcomes with bounded codes such as invalid_arguments, unavailable, authentication_required, denied, timed_out and outcome_unknown, plus safe remediation and retry policy. Keep result data separate from acceptance evidence. Preserve valid structured JSON under truncation, with truncation metadata instead of slicing serialized JSON. |
| 4 | Propagate cancellation and per-tool recovery | Pass the turn signal/deadline into executors. Read cancellation and uncertain external completion need different outcomes. Longer remote operations can later expose operation handles, status reads and completion events tied to existing receipts, without a second workflow engine. Keep source-owned replay policy and existing receipt checks. Verify interruption never becomes an automatic duplicate external action. |
| 5 | Explicit principal and trigger context before management tools | Carry trusted caller authority separately from bot identity and trigger (interactive, scheduled, webhook, delegated). The default bot is not the owner. Scope status/search now; design broader management authority before exposing it. |
| 6 | Common tool/interaction conformance checks | For every new tool, exercise API/Ollama/ACP exposure or a truthful unsupported reason, input failure, availability, permissions, secret filtering, cancellation, duplicate resolution and unknown completion. Use durable backend approval state for settled cards; never browser-local state as authority. |

These are engineering recommendations inferred from the compared sources and OpenAg's current structure. Start with **catalogue + availability + focused tool guidance**, using `openag_help` and `openag_status` as the first consumers. Then prove one existing tool family end to end—computer status/screenshot is a useful bounded example—before broadening other capabilities. Third-party MCP parity and management actions deserve separate scope decisions.

## Limits

This was a selective source comparison, not a complete security or production audit. No peer application was run, and no uptime, scale or real-provider success was measured. OpenAg's recent full Vitest run failed; baseline attribution was not performed here, so those failures remain an independent confidence limit. No application code, configuration, tickets or live state changed. This note is not a request to implement or deploy the recommendations.
